# De-Droid Python Documentation

This document explains the complete Python side of De-Droid from basic setup to advanced behavior.

It covers all Python entry points in this repository:

- `model-api/scripts/build_variant_dataset.py`
- `model-api/scripts/build_training_dataset.py`
- `model-api/scripts/train_safety_model.py`
- `model-api/model-api/main.py`

If you are new to this project, start at **Quick Start (From Scratch)** and then follow **End-to-End Workflow**.

## 1) What the Python code does

The Python code powers De-Droid's intelligence layer.

- It builds and normalizes training data from multiple sources.
- It trains a safety classifier for Android package removal risk.
- It exports runtime prediction files used by the desktop app.
- It exposes a FastAPI service for package safety checks.
- It applies hard safety guardrails to reduce dangerous recommendations.

In short: **raw package data in -> normalized dataset -> trained model + predictions -> API/runtime safety results out**.

## 3) Quick start (from scratch)

Run these commands from the repository root (`de-droid/`).

### 3.1 Prerequisites

- Python 3.11+
- pip

### 3.2 Create virtual environment

```bash
python3 -m venv model-api/env
source model-api/env/bin/activate
```

### 3.3 Install dependencies

```bash
pip install -r model-api/requirements.txt
```

Installed libraries include:

- `scikit-learn`, `scipy`, `numpy`, `joblib`
- `fastapi`, `uvicorn`, `pydantic`

### 3.4 Build training dataset

```bash
python3 model-api/scripts/build_training_dataset.py
```

### 3.5 Train model and export predictions

```bash
python3 model-api/scripts/train_safety_model.py
```

### 3.6 Run API server

```bash
uvicorn main:app --app-dir model-api/model-api --host 0.0.0.0 --port 8000 --reload
```

```bash
curl http://127.0.0.1:8000/health
```

## 4) Safety labels and hard guardrails

The whole Python pipeline uses a 4-level label system:

- `RECOMMENDED`: generally safe to remove
- `ADVANCED`: removable with caution
- `EXPERT`: potentially system-impacting
- `UNSAFE`: do not remove

Risk order (used when merging conflicting labels):

- `RECOMMENDED` < `ADVANCED` < `EXPERT` < `UNSAFE`

Hard safety gates are applied in both training-time outputs and API/runtime checks:

- `critical_system_denylist`: critical package is always forced to `UNSAFE`
- `android_core_system_keyword`: risky `com.android.*` packages are upgraded to at least `EXPERT`
- `low_confidence_safety_upgrade`: low-confidence `RECOMMENDED` is upgraded to `ADVANCED`

These gates are deterministic safeguards on top of model predictions.

## 5) End-to-end workflow

This is the intended sequence:

1. (Optional) Build OEM variant files from community raw lists.
2. Build canonical training dataset.
3. Train model and generate report, predictions, and playbook.
4. Run FastAPI service and/or use generated prediction JSON in desktop app.

### Typical command chain

```bash
# Optional OEM variants
python3 model-api/scripts/build_variant_dataset.py --oem XIAOMI --input-dir model-api/raw-data/redmi --out model-api/raw-data/variants_redmi.json

# Canonical dataset
python3 model-api/scripts/build_training_dataset.py --variants model-api/raw-data/variants_samsung.json model-api/raw-data/variants_redmi.json

# Model training + artifacts
python3 model-api/scripts/train_safety_model.py --dataset model-api/processed/training_dataset.json

# API
uvicorn main:app --app-dir model-api/model-api --host 0.0.0.0 --port 8000
```

## 6) Script documentation

## 6.1 `build_variant_dataset.py`

Path: `model-api/scripts/build_variant_dataset.py`

### Purpose

Converts raw OEM community lists (text/table files) into normalized variant JSON rows that can be merged into the main training dataset.

### Supported inputs

- List-style files with sections such as `safe_to_remove`, `use_with_caution`, `do_not_remove`
- Table-style files (tab-separated) with package name and safe-to-disable signal
- Either:
  - explicit `--list-file` and `--table-file`, or
  - `--input-dir` that contains raw files

Current `--input-dir` file suffix support in code:

- `.txt`, `.tsv`, `.csv`, `.list`, `.sh`

### Key parsing behavior

- Extracts package IDs via regex and normalizes to lowercase.
- Filters generic prefixes such as `com.android` (not full package IDs).
- In list files:
  - `safe_to_remove` -> incoming label `ADVANCED`
  - `use_with_caution` -> incoming label `EXPERT`
  - `do_not_remove` / `do not uninstall` / `bootloop` -> incoming label `UNSAFE`
- In table files:
  - `Safe To Disable` yes -> `ADVANCED`
  - no / not recommended -> `UNSAFE`
- For duplicates, keeps the safer (higher-risk) label via `safer_removal()`.

### CLI options

- `--oem` (default: `SAMSUNG`): OEM tag stored in output rows
- `--list-file` (default: `model-api/raw-data/samsung-bloatware-list.txt`)
- `--table-file` (default: `model-api/raw-data/samsung-data-table.txt`)
- `--out` (default: `model-api/raw-data/variants_samsung.json`)
- `--input-dir` (default: none): parse all supported files in a directory

### Output format

Writes JSON with:

- `meta`: OEM name, row count, source stats
- `packages`: normalized package rows sorted by package ID

Each package row includes fields like:

- `id`, `list`, `description`, `removal`, `category`
- `dependencies`, `neededBy`, `labels`, `alternatives`, `source`

## 6.2 `build_training_dataset.py`

Path: `model-api/scripts/build_training_dataset.py`

### Purpose

Builds the canonical ML dataset by merging:

- UAD raw data (`uad_lists.json`)
- desktop app curated list (`debloat_lists.json`)
- optional OEM variant files from `build_variant_dataset.py`

### What it normalizes

- Removal labels to canonical set: `RECOMMENDED`, `ADVANCED`, `EXPERT`, `UNSAFE`
- Category labels to: `BLOATWARE`, `OPTIONAL`, `ESSENTIAL`
- string/list fields (trim, dedupe, sort)

### Merge strategy

- Starts with UAD rows keyed by package ID.
- Merges desktop rows over UAD when present.
- Optional variant rows are merged after that.
- Any label conflict is resolved with safer label (higher risk).
- Sources are combined in `source` (example: `desktop+uad+variant:redmi`).

### Derived training features written per row

Besides original fields, output rows include:

- `text`: combined free text field for NLP features
- `dep_count`, `needed_by_count`, `label_count`
- `has_alternatives` (0/1)
- `source_confidence` (weight used during model training)

`source_confidence` policy:

- desktop + uad: `1.0`
- uad only: `0.95`
- desktop only: `0.9`
- variant-only rows:
  - `UNSAFE`: `0.8`
  - `EXPERT`: `0.65`
  - others: `0.55`
- fallback: `0.75`

### CLI options

- `--uad` (default: `model-api/raw-data/uad_lists.json`)
- `--desktop` (default: `desktop-app/src/data/debloat_lists.json`)
- `--out` (default: `model-api/processed/training_dataset.json`)
- `--variants` (default: none, accepts multiple files)

Variant file formats accepted:

- object with `packages: [...]`
- raw list `[...]`

### Output

Writes `training_dataset.json` with:

- `meta`: dataset count, label distribution, source stats/conflicts
- `rows`: full canonical and feature-enriched rows for training

## 6.3 `train_safety_model.py`

Path: `model-api/scripts/train_safety_model.py`

### Purpose

Trains the safety classifier, evaluates trust metrics, applies safety gates, and exports all runtime artifacts.

### Training pipeline overview

1. Load canonical rows from `training_dataset.json`.
2. Oversample minority classes:
   - `UNSAFE` x4
   - `EXPERT` x2
3. Build features:
   - word TF-IDF (1-2 grams)
   - character TF-IDF (3-5 grams)
   - OEM one-hot feature
   - numeric metadata features
   - package-structure features (prefixes, keywords, critical denylist flag, etc.)
4. Train/test split with stratification.
5. Train two models:
   - calibrated SGD classifier
   - logistic regression
6. Blend probabilities: `0.4 * SGD + 0.6 * LR`.
7. Apply safety gates to predictions.
8. Compute metrics and confusion matrices.
9. Run OEM holdout evaluations and release criteria checks.
10. Export model artifact, report, predictions, and OEM expansion playbook.

### Important metrics generated

- accuracy, macro F1
- per-class precision/recall/F1
- `UNSAFE` recall
- false-safe rate (`UNSAFE` predicted as not `UNSAFE`)
- confidence coverage at threshold `>= 0.8`
- expected calibration error (ECE)

### Explainability output

Per-package predictions include `top_factors` built from model feature contributions (humanized labels such as keyword matches, OEM hints, and structural package clues).

### CLI options

- `--dataset` (default: `model-api/processed/training_dataset.json`)
- `--model-out` (default: `model-api/models/safety_baseline.joblib`)
- `--report-out` (default: `model-api/models/safety_baseline_report.json`)
- `--max-features` (default: `12000`)
- `--predictions-out` (default: `model-api/models/safety_predictions.json`)
- `--predictions-out-desktop` (default: `desktop-app/src/data/safety_predictions.json`)
- `--playbook-out` (default: `model-api/processed/oem_expansion_playbook.json`)

### Output artifacts

- Model artifact: `safety_baseline.joblib`
- Report: `safety_baseline_report.json`
- Runtime predictions: `safety_predictions.json`
- Desktop predictions copy: `desktop-app/src/data/safety_predictions.json`
- OEM onboarding/playbook: `oem_expansion_playbook.json`

## 6.4 `main.py` (FastAPI service)

Path: `model-api/model-api/main.py`

### Purpose

Provides HTTP endpoints for package safety checks.

### Startup behavior

At startup, it tries to load:

- precomputed predictions JSON (`safety_predictions.json`)
- model joblib artifact (`safety_baseline.joblib`)

Lookup order:

1. `model-api/model-api/models/`
2. fallback to `model-api/models/`

### Inference behavior

- Uses precomputed predictions when package exists in cache.
- Applies deterministic safety gates after cached prediction.
- For unknown packages, uses heuristic classifier (keyword and namespace logic).
- Returns sorted results by severity: `UNSAFE`, `EXPERT`, `ADVANCED`, `RECOMMENDED`.

### Request/response models

- Request body (`/api/check-packages`):
  - `packages: list[str]` (required)
  - `device_brand: str | null` (optional; currently accepted but not used in logic)
- Response items include:
  - `package_id`, `label`, `confidence`
  - `top_factors`, `safety_gate`, `oem_cohort`, `is_bloatware`

## 7) API endpoint reference

Base URL example: `http://127.0.0.1:8000`

### `GET /health`

Health and model-loading status.

Example:

```bash
curl http://127.0.0.1:8000/health
```

### `POST /api/check-packages`

Batch safety check for many package IDs.

Example:

```bash
curl -X POST http://127.0.0.1:8000/api/check-packages \
  -H "Content-Type: application/json" \
  -d '{
    "packages": [
      "package:com.facebook.katana",
      "com.android.systemui",
      "com.example.unknown.app"
    ],
    "device_brand": "SAMSUNG"
  }'
```

Notes:

- `package:` prefix is automatically removed if present.
- Empty/invalid package list returns HTTP 400.

### `POST /api/check-single`

Single package check.

`package_id` is a query parameter.

Example:

```bash
curl -X POST "http://127.0.0.1:8000/api/check-single?package_id=com.android.systemui"
```

### `GET /api/stats`

Returns model/prediction cache statistics, label distribution, and OEM distribution.

```bash
curl http://127.0.0.1:8000/api/stats
```

### `GET /api/critical-packages`

Returns critical package denylist and count.

```bash
curl http://127.0.0.1:8000/api/critical-packages
```

### `GET /api/search/{query}`

Search package IDs within cached predictions (max 100 returned).

```bash
curl http://127.0.0.1:8000/api/search/samsung
```

## 7.1 Feedback and self-learning endpoints

These endpoints let the app send user action outcomes to the FastAPI backend so you can generate retraining signals from real usage.

### `POST /api/feedback/events`

Stores one feedback event in local JSONL (`model-api/feedback/events.jsonl`).

Request body:

- `package_id`: Android package id
- `action`: `UNINSTALL | DISABLE | RESTORE | ENABLE | UNDO`
- `outcome`: `SUCCESS | FAILURE`
- optional: `model_label`, `model_confidence`, `device_brand`, `app_version`, `notes`

Example:

```bash
curl -X POST http://127.0.0.1:8000/api/feedback/events \
  -H "Content-Type: application/json" \
  -d '{
    "package_id": "com.example.app",
    "action": "UNINSTALL",
    "outcome": "SUCCESS",
    "model_label": "ADVANCED",
    "model_confidence": 0.63,
    "device_brand": "SAMSUNG"
  }'
```

### `GET /api/feedback/summary`

Returns aggregate feedback stats.

Query params:

- `days` (default `30`)
- `top` (default `20`)

Example:

```bash
curl "http://127.0.0.1:8000/api/feedback/summary?days=90&top=25"
```

### `GET /api/retrain/signals`

Builds label proposals from user feedback (no training is executed yet).

Query params:

- `days` (default `90`)
- `min_events` (default `3`)
- `include_same` (default `false`)
- `limit` (default `500`)

Example:

```bash
curl "http://127.0.0.1:8000/api/retrain/signals?days=120&min_events=4"
```

### `POST /api/retrain/export-variant`

Exports proposals as variant JSON to merge into training dataset.

Default output:

- `model-api/raw-data/variants_user_feedback.json`

Example:

```bash
curl -X POST "http://127.0.0.1:8000/api/retrain/export-variant?days=120&min_events=4"
```

### `GET /api/retrain/commands`

Returns ready-to-run shell commands for dataset rebuild + retraining.

```bash
curl http://127.0.0.1:8000/api/retrain/commands
```

### Desktop app integration behavior

The desktop app now sends feedback events automatically when these actions happen:

- uninstall
- disable
- restore
- enable
- undo

Upload conditions:

- telemetry must be enabled in Settings (`telemetry_opt_in = true`)
- FastAPI server must be reachable

Default upload URL:

- `http://127.0.0.1:8000/api/feedback/events`

Optional override via environment variable:

- `DEDROID_MODEL_API_URL` (example: `http://127.0.0.1:9000`)

## 9) Common workflows

## 9.1 Retrain baseline model

```bash
python3 model-api/scripts/build_training_dataset.py
python3 model-api/scripts/train_safety_model.py
```

## 9.2 Add a new OEM from raw community files

1. Create folder under `model-api/raw-data/<oem>/` and add raw files.
2. Build variant JSON:

```bash
python3 model-api/scripts/build_variant_dataset.py \
  --oem ONEPLUS \
  --input-dir model-api/raw-data/oneplus \
  --out model-api/raw-data/variants_oneplus.json
```

3. Rebuild canonical dataset with variants:

```bash
python3 model-api/scripts/build_training_dataset.py \
  --variants model-api/raw-data/variants_samsung.json model-api/raw-data/variants_redmi.json model-api/raw-data/variants_oneplus.json
```

4. Retrain model:

```bash
python3 model-api/scripts/train_safety_model.py --dataset model-api/processed/training_dataset.json
```

5. Inspect:

- `model-api/models/safety_baseline_report.json`
- `model-api/processed/oem_expansion_playbook.json`

## 9.3 Run API-only checks with existing predictions

If `safety_predictions.json` already exists, you can run API without retraining.

```bash
uvicorn main:app --app-dir model-api/model-api --host 0.0.0.0 --port 8000
```

## 10) Troubleshooting

### Error: file not found during dataset build

- Check default paths exist:
  - `model-api/raw-data/uad_lists.json`
  - `desktop-app/src/data/debloat_lists.json`
- If custom paths are used, pass correct CLI args.

### API says no predictions loaded

- Ensure `model-api/models/safety_predictions.json` exists.
- Or place file in `model-api/model-api/models/`.
- Restart the API after generating artifacts.

### Unknown package gets generic label

- That package is not in prediction cache.
- API falls back to heuristic classification by design.
- Rebuild dataset and retrain to include more known package IDs.

### Model metrics are not meeting release criteria

- Inspect `phase4` and `phase7` in `safety_baseline_report.json`.
- Add better curated OEM variant data.
- Increase validated `UNSAFE` samples and retrain.

## 11) Important implementation notes

- FastAPI currently relies on precomputed predictions for known packages; loaded model artifact is not used for live per-request inference path today.
- `device_brand` in API request is accepted for future use, but current logic does not branch on it.
- Safety gates are intentionally conservative and may override model outputs.
- The desktop app consumes generated predictions from `desktop-app/src/data/safety_predictions.json`.
